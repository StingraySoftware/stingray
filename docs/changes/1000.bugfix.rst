``stingray.utils.mad`` no longer behaves differently depending on whether the optional
``statsmodels`` package happens to be installed. It was imported from ``statsmodels``
when available and otherwise fell back to a local copy that defaulted to ``axis=None``
instead of the documented ``axis=0``, and that rounded the normalization constant to
``0.6745``. There is now a single implementation, built on
``scipy.stats.median_abs_deviation``, which returns exactly what ``statsmodels`` did.
The medians are taken in at least double precision, as statsmodels took them: left in
single precision the MAD of float32 samples around 1e8 comes out half as large again.
Input carrying *more* than double precision now keeps it, which is a genuine
improvement rather than a restoration -- statsmodels reduced float128 input to float64,
discarding the precision such a caller has deliberately asked for.
As a side effect ``import stingray`` no longer pulls in ``statsmodels``, which it was
doing only for this one function, and is about half a second faster.

The baseline fitting in ``stingray.utils.baseline_als`` now builds its sparse matrices
with SciPy's sparse *array* classes rather than the ``spmatrix`` classes SciPy is
retiring. The old spelling raised a ``DeprecationWarning`` on development versions of
SciPy, which the test suite escalates to an error. The replacement was checked to give
bit-for-bit identical baselines on flat, sloped, noisy and spiky input, and on series
too short for the offset correction.
